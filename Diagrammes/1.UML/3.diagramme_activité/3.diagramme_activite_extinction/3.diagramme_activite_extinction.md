# Diagramme d'Activité — Phase 3 : Extinction de l'ESP32

```mermaid
graph TD
    %% Style
    classDef phase fill:#e1f5fe,stroke:#0288d1,stroke-width:2px
    classDef action fill:#fff3e0,stroke:#f57c00
    classDef decision fill:#f3e5f5,stroke:#7b1fa2

    %% Entrées possibles
    Entree((Entree depuis<br/>Phase 1 ou 2))

    %% Déclencheurs d'extinction
    Entree --> Causes

    Causes[Declencheurs d extinction]
    Interrupt[Interruption<br/>Coupure de courant]
    Reset[Reset manuel<br/>ou commande d extinction]
    EchecInit[Echec materiel<br/>en initialisation]

    Causes --> Interrupt
    Causes --> Reset
    Causes --> EchecInit

    %% Point commun : signal d'extinction
    Interrupt --> Signal
    Reset --> Signal
    EchecInit --> Signal

    Signal[Signal d extinction recu]

    %% Étape 1 : Arrêt des actionneurs
    StopIrrig[Arreter irrigation<br/>GPIO26 LOW - Pompe OFF]
    StopVentil[Arreter ventilation<br/>GPIO27 LOW - Ventilation OFF]
    StopLumi[Eteindre eclairage<br/>GPIO25 LOW - Lumiere OFF]

    Signal --> StopIrrig
    StopIrrig --> StopVentil
    StopVentil --> StopLumi

    %% Étape 2 : Vérifier possibilité de communication
    StopLumi --> Connexion{Connexion reseau<br/>disponible ?}

    %% Si connexion disponible
    Connexion -->|Oui| PubFinal[Publier statut final sur MQTT<br/>sai/parcelle1/statut<br/>{ etat: arret, raison: ... }]

    %% Si pas de connexion
    Connexion -->|Non| SkipPub[Publier impossible<br/>Eteindre directement]

    PubFinal --> ArretGPIO
    SkipPub --> ArretGPIO

    %% Étape 3 : Nettoyage final
    ArretGPIO[Desactiver toutes les broches<br/>Mettre les GPIO en securite]
    ArretGPIO --> Save[Optionnel : Sauvegarder etat<br/>en memoire non volatile<br/>pour restauration au prochain boot]
    Save --> Halt

    %% Fin
    Halt((ESP32 hors tension<br/>consommation nulle))

    %% Note sur l'arrêt d'urgence
    Note[Note : En cas de coupure brutale<br/>les etapes peuvent etre sautees<br/>L ESP32 reprendra en Phase 1<br/>au prochain demarrage]
```

### Déclencheurs d'extinction

| Déclencheur | Origine | Comportement attendu |
|-------------|---------|----------------------|
| **Coupure de courant** | Externe (débranchement, panne) | Arrêt immédiat, certaines étapes peuvent être sautées |
| **Reset manuel** | Utilisateur (bouton reset ESP32) | Arrêt propre complet si le temps le permet |
| **Commande d'extinction** | Backend via MQTT | Arrêt propre complet, publication du statut |
| **Échec matériel** | Interne (capteur bloquant, surintensité) | Arrêt de sécurité pour protéger le matériel |

### Séquence d'arrêt

```
1. SIGNAL D'EXTINCTION REÇU
   │
2. DÉSACTIVER LES ACTIONNEURS (ordre séquentiel)
   ├── Pompe → GPIO26 LOW
   ├── Ventilation → GPIO27 LOW
   └── Éclairage → GPIO25 LOW
   │
3. PUBLIER STATUT FINAL (si réseau disponible)
   ├── Topic : sai/parcelle1/statut
   └── Payload : { "etat": "arret", "raison": "...", "timestamp": "..." }
   │
4. NETTOYAGE MATÉRIEL
   ├── Désactiver toutes les broches GPIO
   └── Sauvegarder état en mémoire non volatile (NVS)
   │
5. ESP32 HORS TENSION
```

### Pourquoi un ordre séquentiel ?

Les actionneurs sont désactivés **dans un ordre précis** :
1. **Pompe d'abord** → Évite de laisser l'eau couler si l'arrêt est interrompu
2. **Ventilation ensuite** → Moins critique que la pompe
3. **Éclairage en dernier** → Pas de risque de sécurité

### Sauvegarde en mémoire non volatile (NVS)

L'ESP32 peut sauvegarder en NVS (Non-Volatile Storage) :
- L'état des actionneurs au moment de l'arrêt
- Le mode en cours (Normal ou Dégradé)
- Les seuils configurés
- Le compteur de cycles d'automatisation

Au prochain démarrage (Phase 1), il pourra restaurer ces informations.
